# Проверка безопасности Desktop-Pets — 3 ноября 2026

Проверен `C:\Users\User\Desktop\prikol\pet\Desktop-Pets`. Разделы первоначального аудита ниже описывают состояние **до исправлений**: тогда приложение, установки и сборки не менялись, были созданы только отчёт и запись HANDOFF. После отдельного запроса пользователя код был исправлен; актуальные результаты и оставшиеся ограничения приведены в разделе **Remediation** в конце документа. Исторические свойства проверенного старого EXE сохранены.

## Вывод

В просмотренном исходном коде не подтверждены удалённое выполнение команд, SQL-инъекция, keylogger, установка автозапуска, повышение привилегий или отправка пользовательского ввода. Это результат ограниченного анализа, а не гарантия отсутствия вредоносного поведения: готовый EXE не запускался, исходники не сопоставлены с его Python-кодом, GUI и сетевое поведение процесса не исследовались вживую.

Подтверждена одна небольшая ошибка устойчивости: глубоко вложенные локальные настройки могут оборвать запуск `RecursionError`. Есть потенциальная интерпретация разметки в именах питомцев. В текущем EXE действительно находятся старые Qt 5.15.2 DLL с опубликованными advisories; доступный приложению путь эксплуатации этих CVE не подтверждён. До распространения сборки стоит обновить и зафиксировать сборочные зависимости, проверить фактически вложенные библиотеки и подписывать релизы.

## Что исследовано

- Прочитаны entry point, модели, UI, курсорная координация, обработка мяча, ресурсы, настройки, SQLite, spec и скрипты проверки/сборки. Поиск опасных API дополнен чтением найденных вызовов и их вызывающих сторон.
- Read-only проверены `.dist-info`, `pyvenv.cfg` и версии DLL родительского `prikol\venv`. Сам Python из этого venv не запускался.
- Для EXE проверены SHA256, Authenticode, PE manifest, ASLR/DEP и PyInstaller table of contents. Только две Qt DLL ограниченно декомпрессированы в память для чтения PE version и сравнения SHA256; Python DLL, PYZ и прикладной bytecode не распаковывались и не исполнялись. Файлы из EXE на диск не извлекались.
- Родительский агент проверил SQL payload в временной SQLite с автоматической очисткой и corrupt JSON в MemoryBackend, без изменения реального реестра/данных приложения.
- Публичные advisories сверены с первичными источниками. Файлы, код и хэши не отправлялись внешним сканерам. Антивирусная проверка, динамическая проверка GUI/сети и полноценный анализ всех транзитивных CVE не выполнялись.

## Находки

### S1 — Low, подтверждено: локальные повреждённые настройки могут сорвать запуск

**Где:** `utils/settings_store.py:80`, обработчик исключений `:91`; вызов при старте `main.py:21`.

`json.loads()` не исполняет Python, но способен выбросить `RecursionError`, который текущий обработчик `TypeError, ValueError` не перехватывает. На доступном Inkscape Python 3.12.9 вызов `SettingsStore(MemoryBackend({'pet':'panda','pets':'['*4000+'0'+']'*4000})).load()` воспроизвёл неперехваченное исключение. Реальный HKCU не менялся; та же операция загрузки вызывается до создания основного окна.

**Условия и ущерб:** повреждение значения `pets` либо возможность записать настройки текущего пользователя в `HKCU\Software\DesktopPet`. Это отказ запуска одного приложения у этого пользователя, не remote RCE и не переход к более высоким привилегиям.

**Исправить:** ограничить размер входных настроек до разбора, перехватить `RecursionError`, возвращать безопасные defaults и не затирать повреждённое значение автоматически. Отдельно определить разумный предел количества одновременно восстанавливаемых питомцев: сейчас `ui/pet_window.py:91` создаёт окно на каждую запись. Неограниченное количество — дополнительный локальный ресурсный риск, без доказанного удалённого источника.

### S2 — Low, потенциально: имя питомца попадает в QLabel с AutoText

**Где:** `ui/settings.py:701`, `ui/stats_widget.py:72`; ввод имени `ui/settings.py:426`, сохранение `:733`. Ограничение имени до 80 символов не запрещает `<...>`.

В этих двух QLabel не установлен `Qt.PlainText`. Qt документирует автоматическое распознавание rich text и рекомендует явно определять формат для недоверенного текста. В меню `ui/interaction_panel.py:63` имя уже принудительно plain text. [Документация QLabel для Qt 5](https://doc.qt.io/archives/qt-5.15/qlabel.html#text-prop).

**Сценарий:** имя с HTML-подобной разметкой может изменить отображение; `<img>` потенциально вовлекает загрузку ресурса/декодер. Реальная обработка local/UNC/data URLs на этой Windows/Qt сборке не проверена. Не подтверждены сетевой запрос, утечка файлов, обход разрешений или выполнение кода. Имя обычно задаёт сам пользователь либо локальный редактор его настроек.

**Исправить:** устанавливать `Qt.PlainText` для всех QLabel с пользовательским именем; не вводить HTML escaping как замену явному формату там, где разметка вообще не нужна. Проверить benign имена `<b>name</b>` и `<img ...>` отдельным Qt regression без внешних сетевых ресурсов.

### S3 — Medium, условный риск компонента: в EXE находятся Qt 5.15.2

**Где:** фактические PE-ресурсы `dist/DesktopPet.exe → PyQt5\Qt5\bin\Qt5Core.dll` и `Qt5Svg.dll`; загрузка изображений `utils/sprite_loader.py:99`; неограниченная runtime-зависимость `requirements.txt:1`, `pyproject.toml:14`.

Для обеих DLL подтверждены `FileVersion=5.15.2.0` и точное совпадение с venv DLL. Это не предположение по версии Python wrapper: установленный **PyQt5 5.15.11 не означает Qt 5.15.11**.

Первичные advisories, подходящие по версии:

- **CVE-2023-32763:** Qt сообщает buffer overflow при рендеринге специально подготовленного SVG с вложенным изображением; затронуты версии до Qt 5.15.14 включительно, исправление в 5.15.15. [Qt advisory](https://www.qt.io/blog/security-advisory-qt-svg-1).
- **CVE-2025-5455:** malformed data URL в `qDecodeDataUrl()` может вызвать assertion DoS, если Qt собран с включёнными assertions; затронут Qt до 5.15.18 включительно, исправление в 5.15.19. Наличие assertions в проверенных DLL не установлено. [Qt advisory](https://www.qt.io/blog/security-advisory-recently-discovered-issue-in-qdecodedataurl-in-qtcore-impacts-qt).

**Достижимость:** приложение штатно читает поставляемые локальные PNG/ICO и не имеет диалога импорта SVG или входящего сетевого API. SVG plugin в EXE присутствует, но его наличие не доказывает эксплуатацию. S2 расширяет потенциальный вход в текстовый/ресурсный парсер и требует проверки. Заменить assets в исходной папке способен тот, кто уже имеет локальную запись в эту поставку; это другой уровень доверия. RCE на приложении не воспроизведён, severity upstream нельзя автоматически переносить на этот сценарий.

**Исправить:** выбрать поддерживаемую поставку Qt с актуальными security patches, затем пересобрать и проверить реальные DLL внутри результата. Не считать одно `pip install --upgrade PyQt5` достаточной проверкой Qt. Указанные версии исправлений покрывают только названные CVE, а не весь список последующих проблем. Не принимать недоверенные SVG/другие изображения до проверки границ декодирования.

На дату аудита файлы [PyQt5-Qt5 5.15.19 на PyPI](https://pypi.org/project/PyQt5-Qt5/) предоставлены для Linux/macOS, не Windows. Для Windows понадобится подходящая patched Qt дистрибуция/сборка либо планируемая после тестов миграция на поддерживаемый Qt 6; обещать исправление обычным обновлением wrapper нельзя.

### S4 — Medium для будущего привилегированного релиза, условно: старый builder PyInstaller

**Где:** `prikol\venv\Lib\site-packages\pyinstaller-6.20.0.dist-info\METADATA`; `pyproject.toml:20`, `DesktopPet.spec:19` (onefile EXE).

В доступном builder venv установлен PyInstaller 6.20.0. Maintainer advisory **GHSA-9fxf-4qw3-ghmr** затрагивает версии `<6.22.1`: при привилегированном запуске onefile злоумышленник с контролем окружения может навязать пути bootstrap. Исправление — 6.22.1. [Официальный PyInstaller advisory](https://github.com/pyinstaller/pyinstaller/security/advisories/GHSA-9fxf-4qw3-ghmr).

**Ограничение вывода:** версия bootloader текущего EXE не установлена и не приписывается ему по venv metadata. Manifest проверенного EXE — `asInvoker`, `uiAccess=false`; код не запрашивает elevation. Эксплуатация повышения привилегий для обычного запуска этого приложения не подтверждена. Риск становится существенным, если эту сборку вручную запускают от администратора либо встраивают в привилегированный workflow.

`asInvoker` не запрещает повышенный запуск: процесс может унаследовать elevated token от родителя или быть запущен через Run as administrator. Реальный token работающего процесса не проверялся. Сам PyInstaller отдельно предупреждает о повышенном запуске onefile: [Operating mode](https://pyinstaller.org/en/stable/operating-mode.html).

**Исправить:** обновить доверенную сборочную среду минимум до исправленной версии, пересобрать и зафиксировать происхождение bootloader; не запускать питомца от администратора. Это рекомендация для релиза, не повод обходить текущие ограничения среды.

### S5 — Low/Medium, supply-chain hardening: сборка не зафиксирована и не удостоверена

**Где:** `requirements.txt:1`, `pyproject.toml:2`, `:14`, `:20`; `DesktopPet.spec:9`, `:19`; `scripts/verify.py:96`.

Зависимости и build tools имеют только нижние границы; hash lock/SBOM/подписанной привязки артефакта к ревизии в рассмотренной поставке нет. `--install-deps` у verify явно вызывает pip с `--upgrade` без фиксированных hashes. Это developer opt-in, не скрытая установка при запуске приложения. Такое состояние не доказывает компрометацию пакетов, но следующий build может содержать иной набор транзитивных библиотек.

Текущий EXE **NotSigned**, сертификат и timestamp отсутствуют. Hash устанавливает идентичность проверенного файла, а не доверие к автору. Проверка исходников не доказывает, что именно они находятся в этом EXE.

**Исправить:** воспроизводимый зафиксированный набор runtime/build зависимостей с hashes и доверенным источником; сохранять SBOM/версии DLL и build provenance, подписывать распространяемый EXE. PyPA описывает hash-checking и ограничения доверия к установкам: [Secure installs](https://pip.pypa.io/en/stable/topics/secure-installs/). Никакие установки здесь не выполнялись.

## Браузерный прототип — отдельная граница

`output/menu-concepts/menu-preview.html` не является частью native runtime. Его standalone wrapper загружает Lucide/Floating UI с CDN. Здесь есть внешние запросы при открытии в браузере; это отличается от просмотренного Python приложения. Локальный fragment хранит выбор стиля/паузы, клавиатура используется только для Esc; ввода текста/секретов нет. Отсутствие SRI для внешних scripts — **Low developer-preview supply-chain hardening**, не доказательство утечки данных EXE. Для автономного распространения прототипа стоит локализовать проверенные зависимости или добавить поддерживаемую проверку целостности. Код CDN в этом аудите не проверялся.

## Приоритет следующих действий

1. Исправить S1 и добавить безопасный regression с MemoryBackend; установить PlainText в S2.
2. Перед распространяемой сборкой выбрать patched Qt и актуальный PyInstaller, зафиксировать зависимости, повторить проверку реальных DLL/manifest и привязать EXE к исходной ревизии.
3. На рабочем Qt выполнить GUI-тест resource URLs/имён и освобождения захвата мяча. При необходимости отдельно провести антивирусную и динамическую сетевую проверку без публикации пользовательских файлов.

На момент первоначального аудита исправления намеренно не применялись: исходный запрос был на проверку. Утверждение «приложение полностью безопасно» по этим данным было бы необоснованным.

### Новый advisory Qt6 и оставшиеся действия

Выбранный публичный Windows wheel Qt6 6.12.0 исправляет затронутые исходным аудитом старые Qt5 SVG/data-URL версии. При этом [CVE-2026-105924](https://www.qt.io/blog/security-advisory-cve-2026-105924) описывает отдельный путь QCborValue → JSON на недоверенном CBOR и указывает исправления 6.12.1/6.11.3/6.8.10. Приложение не импортирует QCborValue и не принимает CBOR; settings — обычный JSON. На дату фикса Windows wheel Qt6 6.12.1 в проверенном PyPI release history отсутствовал, поэтому для него не придумывался hash. Заявления «все CVE устранены» нет: после публикации подходящего patched wheel нужен следующий lock update и повторная проверка.

На рабочем Windows CPython 3.13 x64 остаётся выполнить hash-установку, полный Qt6 pytest/smoke и создать отдельный кандидат через `scripts/build_release.py --install`. Старый EXE не подменяется автоматически. Подписание возможно только при появлении личного сертификата; пользователь сейчас выбрал работу без него. Динамическая проверка сети/антивирус и GUI resource-handling также остаются вне выполненных проверок.
